# Deploy flow

## Service repos

```
push to main
  -> GitHub Actions: lint + test
  -> tkozakas/workflows stack-pipeline: build multi-arch image, push ghcr.io/tkozakas/<name>:main
  -> POST $HOOKS_BASE/deploy-<stack> with Authorization: <deploy token>
  -> ingress webhook container runs deploy.sh in /svc/<stack>
  -> docker compose --profile prod pull && up -d --remove-orphans && image prune
```

`deploy.sh` takes a per-stack `flock`, so concurrent deploys of the same stack serialise.

`HOOKS_BASE` is `https://tkozakas.online/hooks`. The hook id is always `deploy-<stack name>`. Manual retrigger:

```sh
curl -X POST -H "Authorization: $DEPLOY_TOKEN" "$HOOKS_BASE/deploy-<stack>"
```

## Deploy tokens

`hooks.json` is generated by ansible from the stack list. Each hook accepts either the stack-specific token (`DEPLOY_TOKEN_<STACK>` from `vault_deploy_token_<stack>`) or the shared `DEPLOY_TOKEN`. A stack whose vault token key is missing accepts only the shared one.

A new stack's webhook does not exist until ansible regenerates `hooks.json` — a CI deploy call before that returns a non-2xx.

## The homelab repo itself

Pushing to `tkozakas/homelab` runs the `Stacks` workflow:

1. Validate: every `docker-compose.yml` under `roles/raspberry-pi/files/` is checked with `docker compose config` against placeholder env values.
2. Deploy changed stacks: the stacks whose files changed in the push get their deploy webhook fired. `jarvis` is excluded. `[skip deploy]` in the commit message skips the whole job.

This copies nothing new to the host by itself — it only restarts stacks whose files the host already has. Changes to `.env` templates, the stack list, `hooks.json` or anything outside a stack directory need an ansible run.

## jarvis task pipeline

A jarvis sandbox task follows the same flow but is watched end to end: after the sandbox exits, the task moves through `pushing`, `waiting for CI`, `deploying`, `verifying`, and only green CI plus a successful deploy reports ok. A failure restarts the sandbox once with the reason.
